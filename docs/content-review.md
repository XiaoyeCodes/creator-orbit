# 独立 Codex 内容复审

新生成任务的图中文字使用 `config/image-copy.json` 中的 `encyclopedia-v2` 策略。图片直接写百科介绍，讲清楚就结束。复审逐页检查底部介绍是否具体、连贯，是否混入制作说明，并连读整组末句，识别重复事实、反驳正文未提出的误解、无必要的纠偏或免责声明式收尾。必要限定贴近相关事实保留，有信息量的正常否定句可以使用；不设关键词黑名单，也不要求统一结尾。新策略图中确有此类问题时先改文字稿，再仅重生成受影响页并核对实际成图。图片介绍和小红书发布短文分别检查，后者的反差与论证示例不套入图片。旧任务（包括 `encyclopedia-v1`）不会因为新的文风偏好自动重画图片。

生成入口的“Codex 内容复审”默认开启，并记住选择。关闭仅跳过新会话复审，仍检查文件、生成证据、字数与原有质量要求。设置在任务建立或点击继续时保存，运行中不改变当前任务。未完成任务也可以在继续前选择是否复审。已有完整作品也可以点击“Codex 复审并修正”。

运行顺序：生成图文 → 另开 Codex 会话逐张看图、核实来源、修正文案或重新生成错误页 → 宿主校验 → 提交队列并就绪。复审失败或取消时保留文件、不提交队列；继续任务从复审阶段恢复。修订前在 `raw_generated/reviews/<runId>/originals/` 保存原图、文案、底稿、manifest 与 page-copy；不自动删除旧版本。

复审报告写到宿主指定的 `report.json`，不是 manifest 内部。格式如下（数组内容是字段结构示例，不是可直接复制的审查结论）：

```json
{
  "runId": "宿主提供的本轮ID",
  "status": "passed",
  "summary": "实际复审结论与修订概述",
  "checks": {
    "facts_checked": true,
    "image_text_read": true,
    "caption_image_consistent": true,
    "all_issues_resolved": true
  },
  "files": [{"path": "相对作品目录的实际文件路径", "sha256": "最终文件的真实SHA256"}],
  "pages": [{"path": "00_封面_主题.png", "observations": "实际看图后的逐页观察：哪些文字、事实、关系得到核实，哪里已修正"}],
  "sources": [{"url": "https://实际来源网页", "claim": "这条来源支持的具体事实"}],
  "issues": [{"description": "原来的具体问题", "correction": "如何修正以及依据", "status": "fixed"}]
}
```

`files` 必须恰好包含最终 manifest 本身、`caption_path`、`full_text_path`、`images[].path`、`images[].copy_path` 的去重全集，不包含报告自身。相对路径的分隔符与宿主 input.json 保持一致；报告必须在所有修订结束后计算摘要。`pages` 对每张最终图片恰好一项，不能漏掉封面。至少保存一条真实来源。没有问题时 `issues: []`；仍有问题使用 `status: "blocked"`，记录未解决项，不以省略问题取得通过。

报告只证明完成了有证据的 AI 复审，不保证事实绝对正确。宿主核对覆盖范围、签核和最终文件摘要；修改文件后复审自动失效。文件证据检查通过与内容语义正确是不同层次，验收结果须如实呈现。

## 阅读感与专业性（reader-narrative-v2）

新文案在事实核查之外，必须独立检查：标题/开头的承诺是否得到回答、段落是否逐步推进主问题、解释是否有具体事实与机制。按 [文案规则](caption-quality.md) 的 `reader_review` 结构，在报告顶层增加同名对象；上面的通用报告示例只展示基础字段，v2 不可省略阅读证据。生成阶段的 `manifest.caption_review.reader_review` 也须同步到最终稿，但不得代替独立阅读判断。

先读正文，写出核心问题与具体收获，摘录真实开头与答案；逐段记录信息增量、冗余、断裂或抽象泛论及实际改法。编辑后再核实新增事实、比较、类比和因果，保留争议边界。未兑现标题、仍为名词摘要或只写空泛结论时，修正后再签核，未解决则 blocked。不要因普通词语、无 emoji 或未套固定三段格式判失败。

正文可以用重点案例讲透问题，由完整底稿与图片覆盖全部选题对象。复审不得为追求逐项完整重新塞回十段摘要；核对整组图文范围、标题承诺与图文一致性。只改文风时保留合格图片，确有事实或图中文字问题时按原修正流程处理。旧任务按保存的策略继续；主动发起重新复审采用新规则，并先备份原文件。

普通图文的标题 20 字、正文 1000 字上限依据 [小红书官方电商学习中心](https://school.xiaohongshu.com/lesson/normal/af0fe7e97bb0433fac9da5d1df52b07f) 的公开索引文本，核实日期 2026-10-18。项目保守统计 Unicode 码点，标签、空格、标点、规范化换行计入正文；不宣称完整复刻平台对特殊表情的内部算法。长文功能属于其他入口。

## 措辞与未完成任务（2026-10-18 修订）

项目不设置词语黑名单。“首先、其次、再次、最后、总的来说、综上所述”等均可正常使用；发布文案、完整底稿、图中文字稿和审查记录都不按关键词拦截。旧 Skill 中的对应代码与规则已删除，Codex 按上下文审查事实、表达及图文一致性。字数、真实生成证据和复审报告的文件摘要校验继续保留。

正式任务失败、停止或中断后，可选择“继续处理本篇”，也可以“暂存，开始新创作”或“暂存并换题”。暂存保留原目录和错误记录，不将选题标为已生成；释放占用后恢复换题、选风格和配置编辑。暂存作品可在作品库继续生成或复审，验收合格后仍可准备发布，但不会自动提交旧的队列快照，避免影响新任务的选题进度。

接口 `POST /api/jobs/:id/park` 复用本机令牌校验；运行中不可暂存，登记变更使用与 prepare/commit 相同的排他锁并保存备份。暂存标记先写入任务，再释放登记；恢复旧任务时宿主始终跳过队列提交。
