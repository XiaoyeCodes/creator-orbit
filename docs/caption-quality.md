# 小红书阅读驱动的专业解读文案

新任务使用 `reader-narrative-v2`，写作与阅读复审要求集中在 `config/caption-quality.json`。先研究并完成 `full_text_path` 底稿，再确定阅读角度、写 `caption_path` 发布文案，随后依据完整底稿规划并生成图片。专业解读意味着读者获得具体事实、解释和适用边界；阅读感来自问题被逐步回答，不靠字数、猎奇或统一句式。

## 写作与编辑

1. **选角度**：在 `raw_generated/caption-review.md` 写出三个有资料支撑的阅读角度，选一个核心问题，说明读者困惑和具体收获。问题驱动为默认，允许差异对比、故事解释、场景解答。不强制疑问标题或固定三段结构。
2. **组织正文**：标题和开头提出值得读下去的理由；每段用具体事实推进回答。重点案例讲清“发生了什么—为什么—由此能理解什么”，按题材自然组织，不机械套用这个句式。
3. **图文分工**：完整底稿与整组图片覆盖全部对象；正文可选两三个重点案例，不再要求逐项列全、每项两三句。正文应独立回答主问题，不能只有“见图”；标题若承诺完整清单，应明确清单在整组图中。选题承诺十个对象仍要十个对象的图片，一对象一图不变，不能把正文案例数当成图片数。
4. **读者编辑**：逐段看是否增加具体认识，删重复铺垫，补足有依据的因果环节。不能用“因素复杂、不能只看一点”代替解释；这些词不是禁词，必要的限定仍保留。记录实际问题、修改前后和理由；原稿合格时记录保留依据，不编造修改。
5. **事实复核**：复核编辑新增的数字、比较、类比、因果和叙事细节。事实、解释、作者归纳须可区分；不虚构个人经历、专家身份、人物心理或引语。不确定性在相关论断旁说明，不给每段机械加免责声明。

用户认可的方法示例：从“为什么换了朝代，乱世还没结束？”切入，用具体案例逐步说明政权更替、战争收束和生活恢复的差别。学习问题与案例的关系，不能将历史事实照搬到其他文章，也不能将所有题目都写成这三个步骤。自然题可解释结构与机制，饮食题可用工艺对比，思想题可用适用情境与边界。

发布文案第一行是 `# 标题`，随后空行、正文、标签。标题最多 20 个 Unicode 字符，正文与标签共最多 1000 个 Unicode 字符（含空格、标点、换行，CRLF 统一成 LF；标题后首尾空白不计）。上限来自小红书普通图文的官方公开说明，集中存于 `config/publishing-limits.json`，标签等按保守口径计入；不代表独立长文入口。无论复审开关和历史策略如何，发布准备都会执行字数检查。复杂多对象题以 700–950 字为目标，简单题不强行拉长，也不设置最低字数。底稿应有足够事实与解释，不受这份发布预算约束。

以“十大乱世”为例：底稿与图片解释各阶段的不同机制与后果；正文可用重点案例回答主问题。核实时间范围和具体事实，区分叙述选编与公认排名、事件与长时段、地区差异与全国结论。不能把十个对象合并生图或从整组图文中删去承诺覆盖的对象。不要把方法示例当作未经考证的事实写入成品。

完成真实复读与核查后，在 manifest 中增加 `caption_review`：

```json
{
  "caption_review": {
    "caption_sha256": "最终文案文件原始字节的SHA256",
    "full_text_sha256": "完整解读底稿文件原始字节的SHA256",
    "evidence_path": "raw_generated/caption-review.md",
    "checks": {
      "explains_beyond_listing": true,
      "concrete_facts_and_reasoning": true,
      "reader_friendly": true,
      "claims_grounded_and_qualified": true,
      "caption_image_consistent": true
    },
    "insights": [
      {
        "caption_excerpt": "发布正文中的连续原文，至少20个非空白字符，不含标签或标题",
        "full_text_excerpt": "底稿中支持该解读的连续原文，至少20个非空白字符",
        "explanation": "解释这一段给读者增加了什么认识，具体事实与推理如何对应"
      }
    ]
  }
}
```

`insights` 至少三项，分别选取不重复、不互相包含的正文段落，不用同一句话改摘录范围凑数。上方只展示一项的字段结构。证据文件写出实际发现的问题、修订及来源依据；没有问题就如实说明检查结论，不能捏造修改记录。修改正文或底稿后须重新审查并计算摘要。标签和标题不充当解读证据。

## v2 阅读复审证据

在上面的 `caption_review` 内另加 `reader_review`。独立复审会话也须在自己的报告顶层重新填写同结构的 `reader_review`，不能只引用生成自评。以下为字段说明，必须换成实际原文与判断：

```json
{
  "reader_review": {
    "question": "全文实际回答的核心问题",
    "takeaway": "读者读完能具体复述的认识",
    "opening_excerpt": "最终正文开头的连续原文，不含标题或标签",
    "answer_excerpt": "最终正文中兑现主问题的连续原文，不含标签",
    "explanation": "说明各段怎样推进、引用的事实怎样支持答案，判断标题和开头承诺是否兑现",
    "coverage": "说明正文选例与完整底稿、全套图片的分工，核对选题与标题范围及必要限定",
    "reading_notes": "本轮实际发现的阅读问题、具体位置及修改前后；已合格则说明保留依据，不编造修改",
    "checks": {
      "title_promise_delivered": true,
      "narrative_progression": true,
      "concrete_explanations": true
    }
  }
}
```

`opening_excerpt` 必须从正文起始处连续摘录；`answer_excerpt` 必须确实存在于最终正文中。可保留正文中的 Markdown 格式；不要摘标题或标签充数。正文修改后重新填写引用、更新三处解读与摘要。正文仍可自然结束，无须硬加互动句。

宿主与 Codex 自检都传 `--caption-policy reader-narrative-v2`。程序检查篇幅、原文引用、摘要、字段完整性和三项阅读签核；它不能判断语义上的吸引力、来源是否真正支持论断或保证平台表现。这些必须由 Codex 实际阅读和核实。独立复审关闭时，生成阶段的阅读编辑与证据仍必须通过。

## 兼容性

旧任务的 `captionPolicy` 缺省为 `legacy`；`reader-analysis-v1` 配置保存在 `config/caption-quality-v1.json`。按原策略恢复和验收，不追加 v2 阅读证据要求。历史作品不会自动重写。用户主动“Codex 复审并修正”或在恢复时显式启用复审，会采用当前文案策略；只调整文案时保留合格图片。新测试目录与复用条件包含策略，避免复用旧版成品。
