# 并行图文生成

用户希望一篇生成期间仍能启动其他选题。采用最多 3 篇同时运行的受限并发，生成、复审和验收共用名额。每篇使用独立 Codex CLI 进程、项目目录和选题快照，不增加图像 API 调用渠道。

首页保留创作表单，在上方并列显示运行中的作品。选题、风格、复审开关只作用于新任务。默认选择未占用的第一条 TODO，也可指定其他未占用选题。查看历史、取消和恢复均按任务 ID 操作。

创建请求先串行完成短暂的选题检查和 prepare，避免同时选中同一行；实际生成并行。Map 按任务 ID 保存进程和完成 Promise。第四篇拒绝并说明名额已满，完成或停止一篇后释放名额。关闭服务会等待已接受的准备请求，然后保存并停止各任务，防止 prepare 后留下无主进程。

每篇的 Python prepare/commit 读写自己的 `data/任务选题/<jobId>`，素材保存在 `data/文案/任务/<jobId>`。通过验收后，宿主读取最新公共队列，核对主题、分类、唯一性及预订的原始行，只修改该行状态；保留其他字节，持锁、备份并校验版本。提前落盘预期完成行使崩溃后的同步可幂等恢复。冲突时保留成品、显示原因和重试入口。

旧任务继续按既有目录与登记恢复；旧共享登记占用期间，推迟新任务对公共队列的同步。旧任务完成或暂存后重试待同步项目。失败任务只占用自己的选题，不占运行名额；暂存释放选题，之后恢复为独立作品，不自动更新公共队列。

验证使用临时数据、真实 Python prepare 和可控的独立 worker，覆盖三个并发请求、容量限制、乱序完成、取消、失败重试、手动复审共用容量、服务关闭及恢复、外部队列冲突、幂等恢复、旧共享登记兼容、HTTP 防护。浏览器验证同时创建两篇、分别操作、历史详情稳定和六档响应式宽度。这些测试不替代真实 AI 图文质量验收。
