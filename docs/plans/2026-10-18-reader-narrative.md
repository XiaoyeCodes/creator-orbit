# 阅读驱动文案 Implementation Plan

**Goal:** 将用户认可的问题主线、具体案例和有依据的解释写入后续文案生成及独立复审。

**Architecture:** 新任务使用 reader-narrative-v2；保存 reader-analysis-v1 原规则以兼容旧任务。配置集中定义写作与阅读复审要求，Python 验收生成证据，Node 验收独立复审证据；文件摘要继续绑定最终稿。自动检查不代替事实和阅读质量判断。

**Tech Stack:** JSON、Node.js、Python unittest / node:test。

1. 保存 v1 配置，更新 v2 写作/复审指令及文档。正文可挑选案例，完整底稿与图片保持所有对象和一对象一图，标题承诺必须兑现。
2. 将版本路由贯穿生成、测试复用、宿主验证、独立复审。新增 reader_review：核心问题、收获、开头/答案原文、推进解释、覆盖说明、实际编辑记录与三项签核。
3. 验证器检查实际引用、开头位置、完整字段和签核；v1 / legacy 保留原验证语义。独立复审不得只沿用生成自评。
4. 新增拒绝缺失/伪造/不合格阅读复审和旧版兼容测试，运行相关 Node/Python 测试及语法检查。实际模型写作效果不以结构测试冒充。

不自动改写历史作品，不触发真实生图/发布，不提交既有混合工作区修改。
