# 质量验收与可选交付

## 全部通过才算成功

| 检查 | 通过条件 | 失败处理 |
|---|---|---|
| 主题与数量 | 第一TODO，天然数量严格对应，无固定数量4–8内容页 | 修正规划，不跳题 |
| 真实生成 | 每张文件存在可完整解码；真实调用证据可定位 | 不以提示词或占位图冒充 |
| 原生尺寸 | 每张实际1086×1448，3:4 | 内置GPT重生；禁止本地缩放/裁切 |
| 参考输入 | 每内容页选中七图之一，实际传入，文件与记录一致 | 恢复参考；不可纯文生图降级 |
| 版式继承 | 成图与所选底稿对照，区域关系、层级、密度、图表、底文可辨对应 | 从原底稿重生，不沿用错误首稿 |
| 中文可读 | 主标题、所有关键标签/数字正确，底文手机放大可读 | 重生，不叠字修补 |
| 事实 | 数字、日期、机制、分类有一手来源；来源真实支持论断 | 去掉或修正无证据论断 |
| 图表 | 单位/范围明确、比例合理、地图/流程准确 | 修正/换有证据的分类机制图 |
| 科普底文 | 通常120–180汉字，连贯解释对象/机制/背景意义 | 增补可读正文，不凑短口号 |
| 图文一致 | 主体形态与说明对应，文字与文案无相互矛盾 | 修正后再逐页看图 |
| 风格与标注 | 连续图鉴风格，无手机UI/红框/水印，AI示意如实标注 | 从底稿重新生成 |
| 文案 | 自然开头与结尾提问，禁词不存在，3核心+5–10相关标签无重复 | 重写并核对事实 |
| 完整保存 | 成品/文案/来源/QA/参考调用记录已在持久目录或获授权持久存储 | 保持TODO，保存失败原因 |

逐页读出成图实际出现的全部知识文字，尤其是模型自行新增的标签、图表注释和小字。不能仅对照预先写好的正文：任何新增事实同样必须有来源支持，否则重生去除。

自动脚本检查不能证明科学正确、文字视觉准确、版式像参考或正文真正写得好。QA需逐页记录检查者、时间、结论和证据；不得为了让脚本通过填入未经实际检查的“pass”。有无法确定的项目就标未验证，不能判全部成功。

## 交付回报

说明完成主题、封面/内容页数量、实际检查结果和成品位置。测试报告区分：自动校验通过、人工/模型视觉判断通过、尚未验证。任何问题都如实报告，不把部分通过写成整体完成。测试不等于已安装定时任务、已入小红书草稿或已发布。

## 可选 Google Drive / 同步包

默认本地输出；仅用户显式要求并已授权目标私有目录时采用云盘。技能不含账号、固定云盘ID、令牌或旧授权。实际读写、上传权限由目标宿主处理；缺少连接不应自行公开分享素材或改分享设置。

每篇创建稳定content_id+revision子目录，只含最终图片、manifest.json、READY.json；正文在manifest.body，文案.md/日志/来源等放另外的持久位置。同步manifest与内部QA manifest是不同用途，勿混用。

```json
{"schema_version":1,"content_id":"稳定唯一ID","revision":1,"account_id":"用户配置账号","title":"标题","body":"完整正文含标签","tags":[],"created_at":"带时区ISO8601","images":[{"path":"00_封面_主题.png","sha256":"实际文件摘要"}]}
```

图片按封面先的顺序。相对路径禁止绝对路径、`..`、链接和可执行文件；每图≤25MiB，总包≤250MiB。先上传图片并核对实际文件ID与字节数，再上传UTF-8 manifest，最后READY：`{"manifest_sha256":"manifest实际字节SHA256"}`。全部完成前绝不上传READY。超时先查现有对象，不盲目重复上传。

交付成功另记delivery_status=delivered、实际folder/file IDs、manifest hash与时间；生成状态仍为generated，不是published。已交付改稿用新revision，不覆盖旧包。私有短期下载URL不是永久同步地址。生产队列提交和云盘交付失败分开恢复，已完整生成但交付失败不重新生图。
